# OpenRad 2.0.0 — Monorepo with Android and Python clients

OpenRad 2.0.0 promotes the repository to a monorepo: the Android Kotlin
client and the Python SDK now ship alongside the stable Rust desktop and
CLI, sharing one wire format, one fixture set, and one message catalog.
The Windows installer no longer trips over its own running service, UDP
parsers reject truncated datagrams, and branding uses one canonical logo.

This release includes every change since freshly fetched `origin/main` at
`d2f68d9` (v1.5.0), principally commit `ca487c7` plus this version bump.
Read the [changelog](../../CHANGELOG.md#200--2026-10-13) and the
[complete file inventory](2.0.0-changes.md). Windows remains experimental.

## Downloads and upgrade

Package layout follows v1.5.0: a Linux x86-64 archive (CLI plus desktop,
guides, screenshots, notices, metadata, checksums), an offline Windows
installer with the pinned signed TAP-Windows6 driver, a Windows setup ZIP,
a portable Windows test ZIP, and `SHA256SUMS`.

Run `openrad stop` and close the desktop before replacing binaries or
running the Windows installer. Keep the CLI and desktop from the same
release together. Closing a frontend leaves the shared service running;
stopping it ensures the next start loads the new engine. On Windows, run
the installer with UAC administrator approval: it now stops the old
service before copying, so `Error opening file for writing` on a locked
`openrad.exe` — and the follow-up `An installed file failed its integrity
check: <path>` — should no longer appear. If the integrity message still
appears, it names the divergent file: re-run setup after stopping OpenRad,
then re-download and verify `SHA256SUMS`.

Existing identities, memberships, favorites, join configurations and
credential storage are retained. No identity reset or new device
registration is required.

## Android: alpha to beta

The Android client (`clients/android/`, `com.openrad.mobile`) moves from
alpha to beta. It speaks the same wire protocol as the Rust client over
TCP and WiFi-only UDP, with a packet path about 1.5x faster producing
byte-identical output, verified against golden vectors recorded from the
1.5.0 engine. Its `versionName` is now `2.0.0`. See its
[README](../../clients/android/README.md) for build, install, and WiFi-only
behavior. The parallel `res/values*` string work stays out of this bump.

## Python via git

The Python SDK (`clients/python/`) is a stdlib-only package installable
directly from git:

```sh
pip install "git+https://github.com/gringoestrangeiro/openrad.git@v2.0.0#subdirectory=clients/python"
```

or, from a checkout:

```sh
python3 -m venv .venv && .venv/bin/python -m pip install ./clients/python
.venv/bin/python clients/python/run_tests.py
```

Its version is now `2.0.0` (`openrad.VERSION`, `pyproject.toml`). Live
round-trips against real networks (public joins, private-network auth,
force-relay channels, exact-byte UDP exchanges) were exercised during
this release; reports stay local and out of Git.

## Validation and limitations

- `cargo fmt --check`, the fast `openrad-client` setup tests, the Python
  unit suites (normal plus stdlib-only pass), and `scripts/check-sync.py`
  (fixtures plus locales) pass for this bump.
- The 1.5.0 implementation checks (329 workspace tests, Clippy, Windows
  test compilation, inspected screenshots) are retained unchanged; the
  engine saw only bounds-check hardening since.
- Cross-compilation, synthetic rendering, and live Python playtests do not
  establish native Windows TAP, UAC, credential-store, Direct3D, or real
  Radmin interoperability. Native Windows validation remains outstanding.
  Applications are unsigned; the TAP driver is the unchanged upstream
  signed package.
