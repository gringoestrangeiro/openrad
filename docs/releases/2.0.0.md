# OpenRad 2.0.0 — Monorepo with Android and Python clients

OpenRad 2.0.0 promotes the repository to a monorepo: the Android Kotlin
client and the Python SDK now ship alongside the stable Rust desktop and
CLI, sharing one wire format, one fixture set, and one message catalog.
The Windows installer handles a running OpenRad safely, UDP parsers reject
truncated datagrams, and branding uses one canonical logo.

This release includes every change since freshly fetched `origin/main` at
`d2f68d9` (v1.5.0). Read the [changelog](../../CHANGELOG.md#200--2026-10-14)
and the [complete file inventory](2.0.0-changes.md). Windows remains
experimental.

  screenshots, freedesktop entry and icons with `install-desktop-entry.sh`,

- `SHA256SUMS`: SHA-256 checksums for all distribution files.

## Upgrade

Run `openrad stop` and close the desktop before replacing binaries. Keep the
CLI and desktop from the same release together. Closing a frontend leaves the
shared service running; stopping it ensures the next start loads the new
engine. Existing identities, memberships, favorites, join configurations and
credential storage are retained. No identity reset or new device registration
is required.

On Windows, run the installer with UAC administrator approval. If OpenRad is
running, setup now asks first: **OK** disconnects the VPN through the
installer's own bundled `openrad stop` and closes the desktop window;
**Cancel** quits setup. Setup never force-terminates processes and never runs
an executable already present in the install folder. If an installed file is
still in use afterwards (for example by another Windows user's service), setup
offers Retry/Cancel. An unattended `/S` run performs the same graceful stop
without asking and exits with code 1 if OpenRad is still in use. If the
worker reports `An installed file failed its integrity check: <path>`, it
names the divergent file: re-run setup after stopping OpenRad, then
re-download and verify `SHA256SUMS`.

On Linux, run `./install-desktop-entry.sh` from the extracted folder to add
OpenRad to your application menu. The entry is named after the window app_id
(`org.openrad.desktop`), so docks show the OpenRad icon on Wayland and X11.

## Android: beta

The Android client (`clients/android/`, `com.openrad.mobile`) moves from
alpha to beta. It speaks the same wire protocol as the Rust client over TCP
and Wi-Fi-only UDP, with a packet path about 1.5x faster producing
byte-identical output, verified against golden vectors recorded from the
1.5.0 engine. This release fixes a TUN reader thread leak on interface
rebuilds and a race where renaming the device could stop the VPN service
underneath the new session. The previous debug package
(`com.openrad.mobile.debug`) is a separate app; uninstall it after
installing this one. See its [README](../../clients/android/README.md).

## Python via git

The Python SDK (`clients/python/`) is a stdlib-only package installable
directly from git:

```sh
pip install "git+https://github.com/gringoestrangeiro/openrad.git@v2.0.0#subdirectory=clients/python"
```

Its version is `2.0.0` (`openrad.VERSION`, `pyproject.toml`).

## Build provenance

All artifacts are built from the same committed 2.0.0 source. Linux uses the
established Debian 12 / Rust 1.95.0 builder from a `git archive` of the
release commit. Windows is cross-compiled with Rust's
`x86_64-pc-windows-gnu` target and MinGW-w64, with symbols stripped and local
build paths remapped (see the [Windows guide](../windows.md#linux-cross-build-and-offline-installer)),
and packaged with NSIS and 7-Zip.
The APK is built with Gradle (compile/target SDK 34). Each package carries
its build metadata.

## Validation and limitations

- `cargo fmt --check` passes; **330 default Linux workspace tests pass**
  with eight optional tests ignored; Linux and Windows GNU Clippy pass with
  warnings denied; every Windows workspace test executable compiles. New regressions cover UDP datagram bounds, the ENET
  header check and catalog coverage of the new errors.
- The Android JVM unit tests and the Python suites pass, as does
  `scripts/check-sync.py` (fixtures and locales).
- The Wine installer-flow regression passes with synthetic executables,
  including a running installed `openrad.exe` that unattended repair stops
  through the bundled binary. The interactive prompts were not exercised.
- The freedesktop entry validates with `desktop-file-validate`; the install
  script was exercised in a temporary data directory, not on a live desktop.
- The Android lifecycle fixes are covered by compilation and the existing unit
  suites only; they were not exercised on a device.
- Cross-compilation, synthetic rendering and Wine do not establish native
  Windows TAP, UAC, credential-store, Direct3D or real Radmin
  interoperability. Native Windows validation remains outstanding. Windows
  applications are unsigned; the TAP driver is the unchanged upstream signed
  package.
