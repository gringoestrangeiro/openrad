# OpenRad 1.2.0 — Broadcast controls, forwarding workers and Windows recovery

OpenRad 1.2.0 adds a saved outgoing broadcast recipient shared by desktop and
CLI, moves packet routing off the session orchestration thread, reduces repeated
frontend/setup work, and fixes Windows TAP error 995 after asynchronous setup.
Official Radmin conflict recovery can continue when its service refuses to stop
and now returns readable failure details instead of raw PowerShell CLIXML.

This release includes every changed and added file since v1.1.0, based on freshly
fetched `origin/main` at `eaa98f36867dfaaddab6a8c104da46167ca253e3`.
Read the [changelog](../../CHANGELOG.md#120--2026-10-04) and
[complete file inventory](1.2.0-changes.md). Windows remains experimental.

The Windows assets were subsequently refreshed to prepare Radmin during
installation and strengthen process/adapter recovery. The original Linux
archive and version tag are retained. Refreshed Windows package metadata records
the later source commit; see the [Windows refresh notes](1.2.0-windows-refresh.md).

Run `openrad stop` and close the desktop before replacing binaries or running
the Windows installer. Keep the CLI and desktop from the same release together.
Closing a frontend leaves the per-user service running; stopping it ensures the
next start loads the new engine. Existing identities, memberships, favorites,
saved join lists and storage backends are retained. No identity reset or new
device registration is needed to upgrade.

Both Cargo package versions, the lockfile and all fresh executables report
1.2.0. Linux distribution binaries are built in the established Debian 12 /

newer, in addition to the libraries listed in the Linux setup guide.

## Outgoing broadcast selection

Use **Settings → Outgoing broadcasts** or the CLI to choose one recipient by
RID, exact device name or VPN IP:

```sh
openrad broadcast-peer
openrad broadcast-peer 123456
openrad broadcast-peer 26.1.2.3
openrad broadcast-peer 'Synthetic friend'
openrad broadcast-peer --all
```

The preference is saved by RID and applies to new outgoing frames without
reconnecting. Selecting a RID, querying the setting and restoring all recipients
work while disconnected. Name/IP selection requires a loaded roster and rejects
ambiguous matches. `0.0.0.0` also restores all eligible recipients.

Incoming broadcasts continue arriving from every authorized peer. Unicast and
multicast retain their normal routing. If the selected recipient is offline,
unauthorized, outside the traffic policy or otherwise unavailable, outgoing
broadcasts are dropped without fallback to other peers. Already queued frames
retain the policy that was active when dispatched. See the [CLI guide](../cli.md#outgoing-broadcast-recipient)
and [Brazilian Portuguese guide](../cli-pt-BR.md) for full routing implications.

The desktop saves this setting immediately. Saving or discarding other
preferences does not overwrite a broadcast selection made by either frontend.

## Shared-engine and frontend improvements

- Dispatch outgoing frames and address announcements through one 64-entry
  nonblocking FIFO forwarding mailbox. TAP I/O and session orchestration remain
  on the engine thread; independent peer workers own their encryption state.
- Cache authenticated eligible queue endpoints with IP/RID indexes. Rebuild
  them on membership/channel changes, retain deterministic group ordering and
  duplicate IP bindings, and invalidate retired endpoints through cancellation.
- Validate inbound frames on peer workers and check the channel generation
  again before TAP publication. Buffered old-channel frames cannot inherit the
  authority of a replacement channel.
- Parse incoming peer setup records on the attachment worker, move their owned
  buffers through setup mailboxes and index admission/cleanup by connection and
  peer IDs while retaining bounded queues, duplicate handling and expiry.
- Deduplicate desktop catalog pages in expected linear time, cache joined
  network names and release replaced snapshots outside the notice-queue lock.
  Phase transitions and operation results remain ordering barriers.
- Skip repeated atomic exchanges when a local wake notification is already
  pending. Packet allocations, overlapped buffers and cipher states keep their
  existing ownership/completion contracts.

The [performance guide](../performance.md#cross-platform-forwarding-workers-and-indexed-frontends)
documents the worker split and scoped synthetic microbenchmarks. Those local
measurements do not establish live VPN throughput, process RSS or whole-client
CPU improvement.

## Windows TAP and Radmin recovery

The first overlapped TAP read now starts on the persistent engine thread after
setup handoff. Windows cancels pending I/O initiated by an exiting thread; the
previous setup-worker read could therefore fail with OS error 995 immediately
after a successful setup. A headless pipe regression covers handoff, first read,
repeated polling, rearming and cancellation with owned storage.

The refreshed Windows installer prepares Radmin before TAP creation/repair and
before repeat-install launch. It force-terminates `RvRvpnGui.exe` and
`RvControlSvc.exe` even when service-stop requests fail, and tries validated
NetAdapter, CIM, netsh, PnP and PnPUtil adapter-disable paths. It first runs as
administrator, escalates to SYSTEM on failure and then permits one final
administrator attempt. Two seconds of stable process/adapter state are required.

Every operation remains tied to the selected official GUID/device; unrelated
adapters, profile credentials and service startup settings are retained. The
large immutable program travels through private stdin, while SYSTEM uses an
encoded worker and returns bounded errors over protected IPC. See the
[refresh guide](1.2.0-windows-refresh.md) and
[Windows migration](../windows.md#switching-from-official-radmin-vpn).

## Validation and platform limits

- **293 default Linux workspace tests passed**, with eight optional tests
  intentionally ignored. Coverage includes fixed wire/cryptographic vectors,
  encrypted TCP/UDP traffic, RTT, service IPC, forwarding, incoming offer indexes,
  generation checks, localization and frontend ordering/cache regressions.
- **Five optional offscreen graphics tests passed** with the Vulkan CPU driver.
  Twenty synthetic captures were reviewed, including broadcast controls in all
  four languages at 448 and 832 pixels. The published Portuguese screenshot
  shows complete controls and guidance without clipping.
- **Formatting and Clippy passed for Linux and Windows GNU**, with warnings
  denied. Every Windows workspace test executable compiled.
- **27 synthetic PowerShell recovery cases and eleven setup cases passed**.
  Recovery coverage includes two actual disposable-child/named-pipe error round
  trips, bounded adapter verification, protected-pipe cleanup and plain errors.
  No real Windows service, process, adapter or scheduled task was changed.
- **Eight isolated Wine 11.11 installer-flow cases passed** with dummy executables,
  exercising first/repeat install, custom/default folders, repair, launch and
  missing-uninstaller recovery. Real OpenRad and driver APIs were not executed.
- **Twelve selected Windows Rust tests passed under isolated Wine**: one TAP
  handoff/read/rearm test, nine Radmin address/recovery contracts, one owned-I/O
  test and one trusted-PowerShell construction test. These tests do not execute
  native SYSTEM recovery or use an installed TAP driver.

The initial packages were built from the committed tagged release source.
Refreshed Windows assets use the later committed source recorded in their
build metadata; the original Linux asset is retained unchanged.
Packaging verifies binary versions, ELF/PE architecture and dependencies,
notices, pinned driver/source hashes, the installer manifest, every extracted
installer payload file, and internal/external SHA-256 checksums. Actual Linux
library requirements are recorded in `LIBRARY-REQUIREMENTS.json`.

Default tests remain headless and unprivileged. Optional graphics captures use
synthetic data and a Vulkan CPU driver. No real VPN or active user service is
stopped during automated validation.

Cross-compilation, mocked PowerShell cmdlets, isolated Wine tests and offscreen
Linux screenshots do not establish native Windows TAP, UAC, credential-store,
named-pipe ACL, Direct3D or real Radmin interoperability. Native Windows
validation and live end-to-end performance measurements remain outstanding.
Applications are unsigned; the TAP driver is the unchanged upstream signed
package. The privileged Linux TAP/Polkit session path is not asserted as tested
by synthetic local-child tests.
