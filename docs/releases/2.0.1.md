# OpenRad 2.0.1 — Lighter status updates and client hardening

OpenRad 2.0.1 is a maintenance release. The engine and desktop exchange full
status half as often, the Android TUN reader no longer spins on a failed
interface, the Python client parses and checksums packets with less overhead,
and the Windows installer can also be built natively on Windows. The wire
format, identities and saved preferences are unchanged.

This release includes every change since freshly fetched `origin/main` at
`7416d0f` (v2.0.0), including community pull request #8. Read the
[changelog](../../CHANGELOG.md#201--2026-10-15) and the
[complete file inventory](2.0.1-changes.md). Windows remains experimental.

## Upgrade

Run `openrad stop` and close the desktop before replacing binaries. Keep the
CLI and desktop from the same release together. Closing a frontend leaves the
shared service running; stopping it ensures the next start loads the new
engine. Existing identities, memberships, favorites, join configurations and
credential storage are retained. No identity reset or new device registration
is required.

On Windows, run the installer with UAC administrator approval. As in 2.0.0,
setup asks before stopping a running OpenRad through its own bundled
`openrad stop`, never force-terminates processes, and offers Retry/Cancel
while an installed file is still in use.

## What changed

**Status updates.** The engine publishes its state snapshot every 500 ms
instead of 250 ms, and the desktop polls the shared service at the same
interval. On large networks this halves the full-roster copies made for the
UI. Packet forwarding, keepalives and RTT probes run independently and are
not slowed; peer status and traffic counters can take up to about a second
to appear. Identical, adjacent phase notices are merged; phase transitions
and operation results keep their order.

**Graphics.** When the wgpu renderer is used (the Windows default, or
`--renderer wgpu`), it now prefers an integrated GPU over a discrete one,
among adapters that can present to the window. Software rendering and the
Linux OpenGL default are unchanged.

**Android.** The TUN reader stops on `POLLERR`/`POLLHUP`/`POLLNVAL` without
readable data, on EOF and on read errors, instead of retrying forever. A
spurious zero-byte read of the non-blocking TUN is retried. When the reader
fails while it still owns the current interface, the interface is closed and
reported as failed so it can be retried from the app; a reader from an older
interface generation never closes a newer one.

**Python.** The Internet checksum sums 16-bit words through a `memoryview`
(byte-order corrected), and local API delivery filters subscribers before
parsing so Ethernet-only consumers skip IPv4/UDP validation. The ARP, IPv4
and UDP builders reject MAC addresses that are not six bytes, IPv4 payloads
over the 16-bit total length, and protocol or port values that are not
integers in range.

**Windows packaging.** The desktop build script writes the icon path for
`windres` without the `\\?\` verbatim prefix (keeping UNC shares) and with
forward slashes on Windows hosts. NSIS payload paths use Windows separators;
Linux `makensis` accepts both. The TAP-Windows6 corresponding source is
exported with pinned `core.autocrlf`, `core.eol` and `tar.umask` settings, so
Git for Windows' CRLF default can no longer change the audited archive.
Linux and Windows packages now include the 1.5.0 and 2.0.0 release notes
and inventories in their release history, so changelog links resolve offline.

## Python via git

```sh
pip install "git+https://github.com/gringoestrangeiro/openrad.git@v2.0.1#subdirectory=clients/python"
```

Its version is `2.0.1` (`openrad.VERSION`, `pyproject.toml`).

## Build provenance

All artifacts are built from the same committed 2.0.1 source. Linux uses the
established Debian 12 / Rust 1.95.0 builder from a `git archive` of the
release commit. Windows is cross-compiled with Rust's
`x86_64-pc-windows-gnu` target and MinGW-w64, with symbols stripped and local
build paths remapped (see the [Windows guide](../windows.md#linux-cross-build-and-offline-installer)),
and packaged with NSIS and 7-Zip.
The APK is built with Gradle (compile/target SDK 34). Each package carries
its build metadata.

## Validation and limitations

- `cargo fmt --check` passes; **332 default Linux workspace tests pass**
  with eight optional tests ignored; Linux and Windows GNU Clippy pass with
  warnings denied; every Windows workspace test executable compiles. The
  ignored software-renderer and synthetic screenshot tests also pass. New
  regressions cover adapter ranking and phase-notice coalescing.
- **127 Android JVM unit tests pass** (one skipped), including new TUN poll
  classification tests. The Python `tests/` suites pass with and without
  site-packages, as do the 38 `openrad.py self-test` cases, which add checksum,
  packet-builder and subscriber-filtering regressions. `scripts/check-sync.py`
  passes.
- The Wine installer-flow regression passes with synthetic executables. The
  PowerShell setup/recovery mocks were not run for this release (no `pwsh` on
  the build host); the scripts they test are unchanged since 2.0.0.
- The Android reader changes are covered by compilation and unit tests only;
  they were not exercised on a device. The native-Windows build fixes
  (`windres` path, NSIS separators, archive export) were checked on Linux and
  by reproducing the Git for Windows archive bytes, not on a Windows host.
- Cross-compilation, synthetic rendering and Wine do not establish native
  Windows TAP, UAC, credential-store, Direct3D or real Radmin
  interoperability. Native Windows validation remains outstanding. Windows
  applications are unsigned; the TAP driver is the unchanged upstream signed
  package.
