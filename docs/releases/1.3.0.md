# OpenRad 1.3.0 — Faster initial peer connections

OpenRad 1.3.0 overlaps more of the initial peer setup work, increases bounded
direct-path parallelism and prepares relay pairing while direct candidates run.
Direct connections retain their existing preference window and candidate
deadlines. A prepared relay cannot authenticate the peer or forward traffic
before the existing fallback policy admits it.

This release includes every changed and added file since freshly fetched
`origin/main` at `25afcb86ff52c995b46e0ca9983cae68cd951bd5`, the refreshed
1.2.0 Windows source. Both platforms are rebuilt from the same committed 1.3.0
source. Read the [changelog](../../CHANGELOG.md#130--2026-10-04) and
[complete file inventory](1.3.0-changes.md). Windows remains experimental.

Run `openrad stop` and close the desktop before replacing binaries or running
the Windows installer. Keep the CLI and desktop from the same release together.
Closing a frontend leaves the shared per-user service running; stopping it
ensures the next start loads the new engine. Existing identities, memberships,
favorites, saved join lists and credential storage are retained. No identity
reset or new device registration is required.

Both Cargo package versions, the lockfile and all fresh executables report
1.3.0. Linux binaries use the established Debian 12 / Rust 1.95.0 builder;
Windows x64 binaries are cross-built with Rust 1.98.1 / MinGW-w64. Package
metadata records actual compiler versions, committed source and builder
provenance. The Linux CLI requires glibc 2.34 or newer and the desktop requires
glibc 2.35 or newer, plus the libraries in the [Linux guide](../linux.md).

## Connection changes

- Increase initial capacity from 64 to 96 outgoing peer handshakes and from
  80 to 128 total handshakes, leaving 32 slots available for incoming offers
  when outgoing capacity is full. Established channels do not consume slots.
  Existing retry pacing, failure restraint and backoff remain in place.
- Use four outgoing TCP candidate lanes and interleave public/LAN IPv4/IPv6
  candidates in the first wave. A responsive fourth candidate can progress
  while three others stall. Keep the two-second TCP connect, three-second
  candidate and eight-second lane budgets.
- Connect and pair service-issued relay tickets in a cancellable worker as soon
  as an offer arrives, on both connection roles. Peer authentication retains
  the existing four-second direct head start and eight-second maximum extension,
  including the existing outgoing direct-exhaustion behavior. Preparation
  failures leave direct attempts running. Losing workers are cancelled and joined.
- Validate up to four incoming TCP rendezvous preambles concurrently within the
  existing eight-socket admission bound. A partial preamble no longer blocks a
  healthy accepted socket. TCP peer/service authentication remains serialized,
  with the full selected-socket authentication budget and RID/CID checks.
- Poll Windows nonblocking TCP connects in bounded cancellation intervals,
  without restarting their handshake. Recover shared peer-worker thread
  allocation failures through bounded retries while healthy peers keep running.

Encryption chaining, wire formats, frame validation, identity handling,
authenticated RTT probes and relay-only policy retain their existing contracts.
Relay preparation timing is recorded separately from transport authentication.
See the [architecture](../architecture.md) and [performance](../performance.md)
guides for worker ownership, limits and diagnostic details.

Both platforms also include the Windows installation/Radmin recovery fixes
documented in the [1.2.0 refresh](1.2.0-windows-refresh.md). Existing screenshots
are synthetic illustrations from earlier releases; this release changes no UI
layout and introduces no new screenshots.

## Validation and platform limits

The implementation was validated before release preparation:

- **300 default Linux workspace tests passed**, with eight optional tests
  intentionally ignored. New local-socket regressions cover stalled TCP
  candidates, incomplete incoming preambles, relay pairing overlap, direct
  preference over a prepared relay, rejected preparation and cancellation.
- **Formatting and Clippy passed for Linux and Windows GNU**, with warnings
  denied. Every Windows workspace test executable compiled.
- **43 selected Windows Rust tests passed in isolated Wine**: eleven peer
  connection, eleven scheduling, six transport-I/O, nine direct-candidate and
  six incoming setup cases. Fixtures use synthetic identities and local sockets.

These suites are reused for this release and were not rerun for the version and
release-document updates. Release checks verify the fresh executable versions,
ELF/PE architecture and imports, dependency and standard-library notices,
pinned driver/source hashes, every extracted installer payload file and
internal/external SHA-256 checksums. Build metadata identifies the tagged source
and clean worktree; Linux library requirements are included in the archive.

No real VPN or active user service is stopped during build or package validation.
Cross-compilation and synthetic Wine/socket tests do not establish native
Windows TAP, UAC, credential-store, named-pipe ACL, Direct3D or real Radmin
interoperability. Native Windows validation and public-network connection-time
measurements remain outstanding. Applications are unsigned; the TAP driver is
the unchanged upstream signed package. Faster scheduling and overlapping waits
do not guarantee a direct path through every NAT/firewall configuration.
