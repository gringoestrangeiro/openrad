# OpenRad 0.9.0 — Windows and four languages

OpenRad 0.9.0 brings experimental Windows x64 desktop/CLI support and complete
English, Portuguese, Russian and Vietnamese interfaces. Linux remains the
established platform. macOS support is planned, but work has not started yet.

## Windows status and feedback

Windows has been tested only on Windows 10 so far. The tester reports the client
working perfectly in their setup after preferring native Direct3D/WARP rendering.
That successful implementation is carried into 0.9.0. Windows 11, other hardware,
VM configurations and broader networking/recovery cases still need validation.

The release builder used Linux and did not execute Windows applications or
kernel drivers. The Windows 10 success is real user-provided feedback, separate
from the build and automated checks performed on Linux. Please [open an issue](https://github.com/gringoestrangeiro/openrad/issues/new)
with your Windows version/build, hardware or VM details, renderer, reproduction
steps and relevant logs. More Windows data will help make support stable for
1.0.0. Keep identities, passwords, keys and packet captures private.

## Reported Windows performance

Both clients were observed on the same Windows 10 setup, one joined network,
76 peers:

| Idle measurement | Official Radmin VPN | OpenRad |
| --- | ---: | ---: |
| Memory | 176 MB GUI + 23 MB service = 199 MB | 41 MB client |
| CPU | 1–4% | 0–3% |

CPU usage is broadly similar in this observation; OpenRad uses substantially
less reported memory. These are single-user observations, not a controlled
throughput benchmark. Further CPU and memory improvements are planned.

## Packages and setup

The release has separate Linux x86-64 and experimental Windows x64 packages,
a standalone Windows setup EXE and SHA-256 checksums. Both packages contain
guides, licenses, dependency notices and build metadata. They exclude runtime
profiles, credentials, captures and local logs.

The Linux package is built in Debian 12 with Rust 1.95 to retain a portable glibc
baseline. Keep the CLI and desktop together and run as your normal user; only
the TAP helper uses sudo. See [Linux setup](../linux.md).

The Windows offline installer includes the CLI, desktop and setup worker,
the unchanged signed TAP-Windows6 9.27.0 driver, complete corresponding upstream
source/build scripts and notices, and diagnostics launchers. It creates/repairs
the dedicated adapter, reuses ready installations and opens the desktop;
`--no-launch` supports CLI installation. Normal startup uses administrator
approval. SYSTEM is an explicit diagnostic mode with separate profiles and an
on-demand, signature-checked official PsExec download.

Windows rendering tries native Direct3D 12 hardware, WARP CPU, then OpenGL.
The OpenGL path and explicit renderer flags remain available. Early startup,
Rust panic, native exception and TAP operation diagnostics are included; a
small parent records desktop native exit codes. See [Windows setup and logs](../windows.md).
The driver is installed per machine; the offline setup is self-contained, but
this is not an installation-free or driver-free VPN. Applications are unsigned.
IPv4 Ethernet/ARP at MTU 1500 is supported; IPv6 forwarding and VLAN frames are
outside the current data plane. Native faults can leave temporary IP/routes
until recovery or reboot. The setup retains user profiles and shared drivers
when uninstalling.

## Release verification

The release checks on Linux cover:

- All 182 default workspace tests passed; three optional tests are ignored by
  default. The separate CPU software-renderer pixel check also passed, including
  geometry, clipping and rendered font text.
- Rust formatting and workspace/all-targets Clippy with warnings denied passed
  for Linux and the Windows GNU target.
- Eleven synthetic PowerShell adapter regressions passed, including Windows
  string GUIDs and protected unrelated registry keys. These do not call real
  Windows adapter/driver APIs. The diagnostic launchers are syntax checked.
- Linux and Windows workspace release builds, version checks for the Linux
  executables, Linux ELF/shared-library/glibc inspection, Windows PE/DLL audit,
  NSIS compilation, extracted installer payload hashes, pinned driver/source
  hashes and final archive/checksum integrity are checked during packaging.

The established Linux TAP and idle-peer benchmark checks were run earlier in
this development cycle and were not repeated for release cleanup. Prior Wine
installer-flow checks used synthetic executables only; they establish installer
control flow rather than Windows application or networking behavior.
Native Windows/MSVC build instructions are documented from official Rust
requirements and have not been executed by this Linux release builder. Actual
Windows installer/UAC behavior, WARP/OpenGL across more systems, networking,
credential storage, named-pipe access, cleanup, reconnect and SYSTEM diagnostics
need continued Windows testing and issue reports.
