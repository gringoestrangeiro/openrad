# OpenRad 2.4.5 - detailed changes

## Identity and control plane

- R01, R11: validate identity imports before reserving the profile and share a bounded preference serialization limit.
- R03-R06, N01-N02: distinguish server-side identity replacement, refresh reconnect preferences, enforce dispatch deadlines, serialize uncorrelated private-network joins and preserve known IPC results.
- S01-S03: bind gratuitous ARP to the authenticated peer; verify Windows pipe server identity and executable path; reject unsafe elevated-startup installations. Real elevated-boundary qualification remains pending.

## Networking and platform

- R07-R10, H03: improve TAP cancellation and cleanup, authorize Linux descriptor adoption against the active session and handle malformed Windows frames. Real driver qualification is still pending.
- P01-P02: bound roster admission, worker and packet processing; poll overlapped Windows TAP writes without blocking the engine. The roster ceilings are 1,024 peers, 256 networks, 16,384 links and 1 MiB of text; field measurements remain pending.
- D04: pass explicit control ports into session-specific connection paths; retain compatibility wrappers.

## Desktop, persistence and support

- P03, U02-U03: save network preferences asynchronously, reconcile independent CLI changes and correlate catalog results with both request ID and session generation.
- H04: bound diagnostic-writer shutdown time.
- Provide a structured support bundle containing selected counters and event types rather than raw logs, network names, IP addresses or credentials. Review the preview before sharing.
- Use the Windows SDK resource compiler for MSVC icons and retain GNU windres support.

## Security and maintenance follow-up

- Preserve another writer's temporary file if atomic creation fails.
- Validate Windows I/O buffer lengths and completion state; reject invalid lengths instead of indexing past a buffer.
- Enable AES key schedule zeroization, wipe temporary RSA encoding buffers and unify malformed encrypted-record errors without changing the wire format.
- Add a real disposable coordinator control-plane integration test, four bounded parser fuzz targets, a target-resolved release SBOM and grouped dependency update configuration.
- Record security reporting, dependency policy and release gates. See the [maintenance policy](../maintenance.md).

## Android follow-up

- Stop displaced identities without retry; reject old-session commands and packet traffic.
- Reconcile service and interface ownership across reconnect and shutdown.
- Validate imported identity and transactional roster updates with resource bounds.
- Bound and correlate catalog pagination and batch network operations.
- Expand Android workflow validation. The [combined follow-up report](../audits/openrad-2.4.5-android-review.md) tracks evidence and remaining device qualification.

## Build and qualification

Rust package metadata is 2.4.5. Android release metadata is 2.4.5 (versionCode 12). No other client version was changed. See the [audit checkpoint](https://github.com/gringoestrangeiro/openrad/blob/42eb0995b7fa18006bc92b2637cb3885ccbf086e/docs/audits/openrad-2.4.5-status.md) for per-finding status and recorded Windows validation.

RC 1 qualified Windows TAP installation/removal and Android emulator service lifecycle. Remaining work includes native TAP/TUN packet flow and official-client interoperability, soak testing, desktop quality visualization, incremental status and engine-path consolidation. The Windows named-pipe and startup protections still require production-environment testing. Publication is explicitly authorized by the maintainer with the remaining qualification limitations recorded; no claim of full runtime qualification is made.
