# OpenRad 2.0.2 — Connection and Windows reliability

> **Not published as a stable release.** 2.0.2 reached release-candidate stage only; all of these changes ship in [OpenRad 2.1.0](2.1.0.md).

OpenRad 2.0.2 is a maintenance release based on [merged pull request #9](https://github.com/gringoestrangeiro/openrad/pull/9) and the Android/Linux [peer-presence fix #10](https://github.com/gringoestrangeiro/openrad/pull/10). The wire format is unchanged, so existing OpenRad identities, networks and saved preferences do not need to be recreated.

## Changes

- **Direct-path reliability:** authenticated UDP/TCP direct connections are given time to complete before relay takes over; rendezvous and mapping retries handle endpoint-dependent NAT behavior more reliably.
- **Incoming offers:** the receiving side can obtain its own relay ticket when a direct connection does not succeed, and stale offers are released sooner.
- **Connection deadlines:** IPv4 and IPv6 TCP attempts share a single remaining connection deadline.
- **Windows service startup:** the background service no longer inherits redirected CLI handles, with better startup and exit diagnostics.
- **Desktop configuration:** settings and network preferences are saved atomically to reduce the risk of partially written files.
- **Windows uninstall:** Settings offers a confirmed uninstall flow designed to preserve identities, profiles, preferences and logs.
- **Radmin recovery:** asynchronous diagnostic reads are retained across named-pipe timing races.
- **Localization and tests:** updated Portuguese, Russian and Vietnamese UI strings and regression coverage.
- **Cross-client peer presence:** Android and Linux no longer incorrectly mark newly announced peers offline when the server provides a coordinator but omits presence; explicit offline status and network access checks remain enforced.

## Upgrade

Stop the running OpenRad service and close the desktop before replacing binaries. Keep the CLI and desktop from the same version together. On Windows, use the offline setup package and approve the normal UAC prompt. Existing profiles and identities should be retained; make a backup of important configuration before changing an installation.

## Validation

The merged commit passed the GitHub Actions Rust, Android, Python and cross-client synchronization workflows on 2026-10-20. A separate contributor test on native Windows using an isolated 2.0.2 profile and `--no-tap` connected to the live service, joined a public network, observed authenticated direct UDP/TCP and relay channels, successfully pinged an authenticated peer and disconnected cleanly without affecting the installed 2.0.1 profile.

**Important limitations:** the isolated native Windows test did not activate TAP, exchange IP frames between two 2.0.2 PCs, verify Windows installer/UAC repair or uninstall in a real installation, or demonstrate Radmin's native chat. Native Windows support remains experimental. Real-NAT interoperability and end-to-end packet forwarding should not be inferred from synthetic or no-TAP tests. Linux and Windows packages are unsigned application builds; the offline Windows setup bundles the upstream signed TAP-Windows6 driver.

Android source and automated tests are included in 2.0.2, but an APK must be signed with the existing compatible release key before it can be distributed as an update to the previous Android release. Do not install an independently debug-signed APK over an existing production installation.

## Validated Android/Linux end-to-end traffic

After the peer-presence correction was merged, matching Android 2.0.2 and Linux 2.0.2 binaries built from commit `49316a702b6639a2c9e2b7e83c72232405166858` passed [isolated real VPN tests](https://github.com/mariananetto-sys/openrad/actions/runs/40150185412) using Android 14 + a Linux TAP device, with a private ephemeral network and authenticated relay. Linux to Android ICMP: 3/3 replies, 0% loss, average 74.552 ms. Android to Linux ICMP: 3/3 replies, 0% loss, average 56.690 ms. Both temporary clients and network were cleaned up. This does **not** validate direct UDP/TCP, native Windows TAP peer traffic, long-duration stability, production Android signing or Android in-place upgrade.
