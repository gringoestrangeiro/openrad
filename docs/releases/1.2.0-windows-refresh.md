# OpenRad 1.2.0 — Windows installer and Radmin recovery refresh

The Windows distribution files for 1.2.0 were rebuilt after a report that
installing while official Radmin VPN was running could leave a `26.0.0.0/8`
conflict. Reinstalling with Radmin closed worked in the reported setup. The new
installer therefore prepares Radmin before creating or repairing OpenRad's TAP.

The existing `v1.2.0` tag and Linux archive are retained. Refreshed Windows assets
are built from the later committed source identified by `source_commit` and
`git_base_commit` in their `BUILD-INFO.json`. The GitHub release notes identify
that source commit and the checksum file covers the refreshed downloads.
Both Cargo packages and all new Windows executables continue reporting 1.2.0.

## Installation and recovery behavior

- Run Radmin preparation before first install, repair and the already-installed
  launch path. Invoke it again inside direct configure calls, before inventory,
  TAP driver installation or adapter creation/repair. Failure blocks installation
  before copying files or modifying TAP.
- Discover official adapters regardless of active IP, media state or interface
  name. Terminate `RvRvpnGui.exe` and `RvControlSvc.exe` even if no adapter is
  currently visible or service-stop requests are refused. Use exact executable
  matching for service requests and exact-image force termination.
- Try an administrator child first, then a temporary SYSTEM task, then one final
  administrator child when SYSTEM fails. Both children and scheduler waits are
  bounded. Keep task/pipe cleanup and readable, bounded failure details.
- Try NetAdapter, CIM, netsh, PnP and PnPUtil disabling (including its supported force fallback) when previous methods fail
  to disable the selected device. Revalidate the original GUID, official driver
  description and PnP instance association before every operation. Recognize
  numbered official descriptions such as ` #2`.
- Require both processes to be absent and all selected adapters disabled for two
  consecutive seconds. Retry immediate process restarts/adapter reenablement
  within the ten-second observation window.
- Carry the large immutable initial script through private UTF-8 stdin instead
  of exceeding Windows' encoded-command limit. SYSTEM still executes a fixed
  encoded worker rather than an installed script.
- Include the exact interface, description and IP in remaining address conflicts.
  Unrelated adapters and static/stale addresses on the OpenRad TAP are retained
  as errors. Existing profiles, credentials, Radmin files/drivers and service
  startup/recovery configuration are preserved.

See the [Windows guide](../windows.md#switching-from-official-radmin-vpn) for
details and how to enable the official adapter again, including PnP-disabled
devices. Existing synthetic screenshots and UI layout are unchanged.

## Downloads and upgrade

Use the refreshed `OpenRad-Setup-1.2.0.exe` or
`openrad-1.2.0-windows-x86_64-setup.zip`. The portable
`openrad-1.2.0-windows-x86_64-test.zip` includes the stronger connection recovery
but still requires an installed dedicated TAP adapter.

Disconnect/stop OpenRad and close its desktop before updating, then run the new
installer and accept its normal administrator prompt. The installer handles
closing official Radmin itself. Updated file hashes force repair of older 1.2.0
installations despite the unchanged package version. Existing identities and
saved settings are retained. Verify downloads against the current `SHA256SUMS`.

## Validation and remaining native checks

- 295 default headless Linux workspace tests passed, with eight optional tests
  intentionally ignored. Formatting and Clippy passed for Linux and Windows GNU;
  all Windows workspace tests compiled.
- 42 synthetic recovery cases and eleven adapter-setup cases passed using
  portable PowerShell on Linux. Coverage includes service refusal, both process
  names, all five disable paths, all privilege fallback sequences, exact target
  validation, restart races, PnP-disabled visibility, maximum command size,
  large UTF-8 stdin, real disposable-child/IPC diagnostics and cleanup.
- Nine isolated Wine installer-flow cases passed using dummy executables,
  checking preparation before first/repeat/repair setup and before launch, plus
  refusal before installation files or TAP configuration when preparation fails.
- Fourteen selected Windows Rust address/recovery, TAP handoff, owned-I/O and
  protected PowerShell construction tests passed under isolated Wine. The real Windows
  PowerShell stdin regression is compiled; native execution remains outstanding.
- Fresh Windows builds use Rust 1.98.1/MinGW-w64. Packaging audits PE imports,
  pinned signed driver and corresponding source, notices, exact extracted setup
  payload/worker, installation manifests, documentation links and checksums.
  The original Debian 12/Rust 1.95 Linux archive remains byte-for-byte unchanged.

No user's real VPN is stopped during automated validation. Mocked cmdlets and
Wine do not establish native Windows TAP, UAC, SYSTEM task/ACL, credential-store
or Radmin behavior. This refresh needs a native installation/repair test with
official Radmin initially running. Windows support remains experimental.
