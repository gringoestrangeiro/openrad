# OpenRad 2.4.5 (development)

This development update now targets the Rust desktop client, CLI, persistent VPN service and Android client. Android package metadata remains 2.4.0 pending release approval. Python, Minecraft and the Go server remain outside the development scope.

## Changes

- Validate imported identities before reserving a profile and make large service preferences round-trip safely.
- Harden authenticated peer ARP announcements, Windows named pipes and session replacement handling.
- Improve reconnect policy, command timeouts and TAP interface lifecycle.
- Bound roster admission and packet processing; use overlapped Windows TAP writes.
- Keep desktop network preference writes off the UI thread and reject outdated network search results.
- Validate installation ownership and ACLs before scheduling elevated Windows startup.
- Restore the executable icon in Windows MSVC builds.
- Add a privacy-filtered diagnostic bundle, available in the desktop and with `openrad --json diagnostics`.

- Add local coordinator integration coverage, bounded parser fuzz targets and release SBOM inventory.
- Harden temporary-file ownership, encrypted-record error handling and Windows overlapped I/O bounds.

- Retain bounded Rust peer quality history in status JSON and close pending RTT probes on channel teardown.
- Android: isolate session and TUN generations, drain stale commands, enforce roster and identity admission limits, and make catalog and batch operations session-aware.
- Expand Android CI checks; see the [combined audit follow-up](../audits/openrad-2.4.5-android-review.md).

## Validation and limitations

The latest headless validation passed 388 Rust tests on Windows (two ignored), Clippy with warnings denied, formatting, and a separate disposable local-coordinator integration test. The optimized Windows workspace build passed at the earlier Rust checkpoint and must be rebuilt for the current revision. The executable icon and CLI diagnostic output were checked. The initial development-branch Rust CI also passed on Linux. The new four fuzz targets passed type checking, but instrumented execution on Windows was blocked by the linker; Linux fuzz campaigns, native TAP, official Radmin VPN interoperability, extended soak testing and remaining audit findings still need qualification.

Android validation passed 169 JVM tests (one ignored), lint and debug/instrumentation APK builds. Runtime instrumentation and real VPN interoperability remain unqualified.

This is development documentation, not a published release or a claim of full release qualification.
