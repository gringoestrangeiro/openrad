# OpenRad 2.1.6 — candidata de release

**Estado:** preparacao; ainda nao publicada. Esta versao sucede `v2.1.5`; a tag existente nao deve ser movida. Nao foi alterado o formato de rede, a criptografia de legado, as identidades ou a politica de admissao VPN.

## O que foi corrigido

- **Desktop / Ver versao:** ao abrir a notificacao, a URL da release aparece na propria janela; ha acoes acessiveis para abrir no navegador e copiar o link. Texto e semantica testados em ingles, portugues, russo e vietnamita.
- **Rust Core:** o comando `Stop` ja recebido nao e perdido quando o cliente IPC fecha antes de ler a resposta. O teste de espacamento de joins usa o horario de envio, sem depender do agendamento do receptor. Fixtures de UI paralelas nao entram em conflito.
- **Paper:** os testes de entrega LAN e TCP half-close esperam os eventos relevantes sem depender de um instante de clock especulativo. O protocolo/transporte nao foi alterado por esses dois ajustes.
- **Fabric:** niveis Java do Mixin acompanham o alvo (Java 16/17/21/25), verificacao de **todas** as classes do JAR, atualizacao correta de fontes geradas por alvo, reserva de fila para encerrar o controlador e smoke offline sem tentar IP virtual externo.
- **Android (beta):** uma nova busca de rede cancela uma consulta anterior aguardando resposta; o estado de carregamento e limpo somente pela geracao atual. Teste JVM de corrotinas executado.
- **Python (research/Linux):** token de controle local com tamanho invalido e rejeitado antes de abrir o socket.
- **Pacotes:** historico da versao 2.1.0 e notas historicas 2.1.5 acompanham a documentacao para evitar links quebrados.

## Compatibilidade e escopo verdadeiro

- **Rust Linux:** plataforma principal; requisita TAP e permissao de helper apenas para a interface. **Windows x64 continua experimental** e requer TAP-Windows6; compilar nao prova instalacao e UAC.
- **Android:** beta, Android 8.0+; para distribuir atualizacao da mesma aplicacao e obrigatoria assinatura com a mesma chave oficial. Builds debug sao somente preview.
- **Minecraft Fabric:** builds separados para alvos configurados 1.17–1.21.11 e 26.1–26.3, com Java adequado ao alvo. **1.14–1.16.5 e 1.20 (sem patch) nao possuem adaptador demonstrado; Fabric 1.8–1.13 nao existe neste projeto.**
- **Minecraft Paper:** builds por API para 1.17–1.19.4, 1.20.1–1.20.6, 1.21 e 26.1.1/26.1.2/26.2/26.3. A linha 1.21 reutiliza a API 1.20.6 e nao atesta cada patch; 26.1 sem patch nao foi demonstrado.
- **Python:** prototipo somente Linux; implementa subconjunto TCP/relay, nao todo transporte UDP/ENet do cliente Rust.
- **Interoperabilidade:** vetores criptograficos comuns nao certificam uma sessao simultanea Rust/Java/Kotlin/Python. Interfaces TAP/TUN e o trafego VPN real exigem testes independentes.

## Pendencias antes de publicar como release estavel

1. Builds oficiais Linux e Windows/instalador, verificacao binaria dos arquivos finalizados, manifests e hashes; testar instalacao, desinstalacao, TAP e UAC em Windows real.
2. Executar a suite Android num runner com SDK e testar consentimento VPN, reconexao, troca de rede, revogacao e assinatura de producao em dispositivo. Nao publicar um APK de depuracao como oficial.
3. Executar Python em Linux, em ambiente isolado; e pelo menos um teste de carregamento Fabric/Paper **por familia de API** e um login/jogo completo com peer autorizado, sem perfis ou credenciais reais de usuarios.
4. Revisar os riscos ainda condicionados de lifecycle Android, logs Unix e divergencia de membership entre implementacoes. Nenhuma mudanca incompatível de protocolo deve entrar sem contrato, fixtures e testes cruzados.

O pedido de release nao equivale a evidencias inexistentes. A candidata pode ser distribuida para testes, mas a promocao para canal estavel depende da validacao acima.
