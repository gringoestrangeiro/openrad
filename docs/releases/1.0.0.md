# OpenRad 1.0.0 — Shared sessions, network workflows, and transport efficiency

OpenRad 1.0.0 ships fresh Linux x86-64 and Windows x64 binaries from the same
release source. It includes every local change since remote v0.9.5: the desktop
and CLI now share one persistent service, network management is easier, identity
reset/provisioning is bounded and observable, and the data path avoids additional
allocations and repeated work.

Read the [full changelog](../../CHANGELOG.md#100--2026-10-01) for every behavior
change and the [complete file inventory](1.0.0-changes.md) for all 53 changed or
added files. Windows support remains experimental in this 1.0.0 release; the
version number does not replace native-platform validation.

## Download packages

- `openrad-v1.0.0-linux-x86_64.tar.gz`: newly compiled Linux CLI/desktop, guides,
  screenshots, complete changelog/change inventory, build/library requirements,
  standard-library/dependency notices, and internal checksums.
- `OpenRad-Setup-1.0.0.exe`: offline Windows installer with the CLI, desktop,
  setup worker, unchanged signed TAP-Windows6 9.27.0 driver, corresponding driver
  source/build scripts, dependency/installer/runtime notices, and documentation.
- `openrad-1.0.0-windows-x86_64-setup.zip`: that installer as `OpenRad-Setup.exe`,
  plus release/validation/build/import/driver information, documentation,
  screenshots, and internal checksums.
- `openrad-1.0.0-windows-x86_64-test.zip`: portable Windows application files,
  launcher/diagnostic tools, documentation and dependency notices. It requires
  the dedicated installed TAP adapter and elevation to connect; the offline
  setup is the usual installation route.
- `SHA256SUMS`: checksums for all four distribution files. GitHub also provides
  the tagged source archives. No 0.9.0 Linux binary is reused in this release.

Both application binaries report 1.0.0. Linux release binaries are built in the
established Debian 12 container with Rust 1.95.0; their audited minimum glibc
requirement is **glibc 2.34 for the CLI and 2.35 for the desktop**, so the complete
package requires glibc 2.35 or newer. Per-binary requirements are also recorded in
`LIBRARY-REQUIREMENTS.json`. Windows binaries
are cross-built with Rust 1.98.1/MinGW-w64. Packaging inspects ELF or PE
architecture/dependencies and rejects missing Linux libraries or unknown Windows
runtime DLLs. Applications remain unsigned; the bundled TAP driver is upstream's
unchanged signed package. Package metadata records the source commit/tree,
toolchain, driver provenance, and checksums.

## Upgrade and shared session behavior

1. Stop the previous session with desktop **Disconnect** or `openrad stop`,
   close the previous desktop, and replace both Linux binaries together or run
   the new Windows setup. An old background service keeps its old code until
   explicitly stopped and restarted.
2. Start either frontend first. Both attach to one service for the selected
   profile, using the same saved identity, networks, peers, and virtual interface.
   Keep `openrad` beside `openrad-desktop`, since the desktop launches that service
   through the CLI executable.
3. Closing a terminal or desktop window leaves the VPN running. Desktop
   **Disconnect** or `openrad stop` stops it for both frontends. Different profiles
   remain separate; the virtual interface is exclusive across active profiles.

New default profiles use `$XDG_STATE_HOME/openrad` (usually
`~/.local/state/openrad`) on Linux and `%LOCALAPPDATA%\openrad` on Windows. If no
canonical CLI profile has been initialized, an existing desktop profile with
saved settings is retained. Use the same `--data-dir PATH` with both applications
for an explicit profile. Existing desktop identities stay in the credential
store; CLI-created identities retain their private file storage. Use `start`
with an existing identity; `init` refuses to replace a profile or running session.

The Unix desktop/CLI raise their soft open-file limit to 8192, within the existing
hard limit, so larger peer rosters have room for sockets and wake descriptors.
Higher inherited limits are preserved. This needs no sudo, logs restrictive
limits, and never prevents startup solely because the adjustment failed.

## Features and operational changes

- **Favorites and Auto join:** pin public/private favorites, select networks,
  enter private passwords, and submit overlapping joins at least 50 ms apart
  with independent results. Save up to 32 named lists of 128 networks; they
  survive identity replacement and contain names/access types without passwords.
  Joining starts only after the explicit Join button. Already joined/pending
  memberships are skipped. A refusal does not cancel other joins; ambiguous
  legacy password replies require reconnecting and joining private networks
  individually.
- **Discovery and layout:** searches update after a 300 ms typing pause and
  discard stale replies. Scroll all joined networks in a resizable sidebar with
  a fixed device footer; scroll the network selector horizontally. Responsive
  connection cards and cached/measured peer rows retain translated layouts.
- **RTT, names, and relays:** use peer **Test RTT** or `openrad ping PEER_RID` for
  a correlated authenticated keepalive probe with a 3000 ms deadline. Rename a
  registered device without replacing its identity/memberships. Save **Force
  Relay** or `openrad force-relay true` to suppress direct setup in both
  directions and reconnect the current channels.
- **Release notices:** check the latest stable GitHub release at launch and
  hourly, show a retained dismissible link, and compare semantic versions.
  Optional checks use system curl with HTTPS-only redirects, certificate
  verification, bounded response size and a 15-second transfer budget. Install
  curl on Linux; a failed check does not affect the VPN.
- **Identity reset:** cancel queued connection work, bound service shutdown,
  show provisioning/retry/redirect/save progress, retain the previous identity
  until saving succeeds, and retry only storage for an issued replacement.
  Transient pre-registration failures get up to three attempts per server and
  a 90-second aggregate network budget. An ambiguous lost registration response
  is never automatically resent. Failed reset state remains visible; a
  successful reset finishes disconnected. A new identity does not inherit old
  memberships. Copy the reset log path from Settings for safe diagnostic stages.
- **Transport efficiency:** cache UDP send-window/retry metadata, bypass
  in-order reorder-map work, reassemble fragments in one buffer with bounded
  receipt/coverage tracking, validate complete incoming records then retain
  owned/shared frame buffers, batch counters, borrow/reuse membership metadata,
  serialize immutable snapshots outside the state lock, move desktop JSON
  subtrees, and translate Windows MAC headers directly in persistent overlapped
  write storage. Wire formats, encryption/authentication, MTU, ACK admission,
  retry intervals/limits, and traffic policy remain enforced.
- **Languages and documentation:** add 100 complete messages across English,
  Portuguese, Russian, and Vietnamese, update all guides/repository rules,
  include five public synthetic screenshots, and restore the full published
  0.1.0–1.0.0 changelog history.

## Platform limits

The real Windows TAP driver, UAC/setup/catalog trust, current-user named-pipe
security, credential storage, service lifetime/reset, Radmin SYSTEM recovery,
Direct3D/WARP behavior on more hardware, Windows 11, and live interoperability
require native Windows testing. Previous Windows 10 success/performance feedback
was supplied by a user for 0.9.0; this Linux release builder has no new native
Windows VPN session to report. Wine checks and synthetic screenshots establish
only their stated scope.

The privileged Linux TAP test and optional idle-worker CPU benchmark were not
rerun for release preparation. Existing Linux TAP validation and older isolated
performance tables remain historical evidence. No new end-to-end throughput,
whole-process RSS, live public-network/NAT test, or completed security audit is
claimed. IPv4 Ethernet/ARP at MTU 1500 is supported; IPv6 forwarding/VLAN frames
and a macOS data plane remain outside this release.

Use the [Linux](../linux.md), [Windows](../windows.md), [desktop](../desktop.md),
and [CLI](../cli.md) guides for installation, profile and credential-store
requirements, diagnostics, and recovery. Keep identities, passwords, keys,
captures, and operational reports private when reporting issues.
